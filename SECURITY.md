# Security Policy

Thank you for helping keep this project and its visitors safe.

## Supported Versions

This is a personal portfolio site deployed as a single, continuously-updated application.
Only the **latest version** on the `main` branch (and what is live in production) is supported.

| Version        | Supported          |
| -------------- | ------------------ |
| `main` (latest)| :white_check_mark: |
| Older commits  | :x:                |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

If you discover a security vulnerability, report it privately using one of the following:

1. **GitHub Security Advisories** (preferred) — open a private report via the repository's
   [**Security → Report a vulnerability**](https://github.com/raunak0400/RaunakJ.wtf/security/advisories/new) tab.
2. **Email** — [raunakkumarjha233@gmail.com](mailto:raunakkumarjha233@gmail.com) with the subject line
   `SECURITY: <short summary>`.

To help triage quickly, please include:

- A clear description of the vulnerability and its potential impact.
- Step-by-step instructions to reproduce it (proof-of-concept if possible).
- The affected URL, page, component, or dependency.
- Any relevant logs, screenshots, or request/response captures.

## Response Expectations

- **Acknowledgement:** within **72 hours** of your report.
- **Assessment & triage:** within **7 days**, including a severity evaluation.
- **Fix & disclosure:** timelines depend on severity and complexity; you will be kept informed of progress.

If the report is accepted, a fix will be prepared and deployed. If it is declined, you will receive an
explanation. With your consent, you will be credited for the discovery.

## Scope

**In scope**

- The production portfolio site and its source code in this repository.
- Dependency vulnerabilities that are exploitable in this project's context.

**Out of scope**

- Vulnerabilities in third-party platforms (e.g., Vercel, GitHub, npm) — report those to the respective vendor.
- Denial-of-service (DoS/DDoS), volumetric, or brute-force attacks.
- Social engineering, phishing, or physical attacks.
- Best-practice or informational findings with no demonstrable security impact
  (e.g., missing headers with no exploit path, verbose banners).
- Automated scanner output without a validated, reproducible issue.

## Safe Harbor

Good-faith security research conducted in accordance with this policy is welcomed. Please avoid privacy
violations, data destruction, service degradation, and any access beyond what is necessary to demonstrate
the vulnerability. Do not access, modify, or exfiltrate data that is not your own.

Thank you for practicing responsible disclosure.
